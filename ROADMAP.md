# Community Meetings roadmap

This roadmap lists ideas being considered for future releases. It has no
release dates, and priorities may change as the project evolves. The current
features are documented in the [user guide](https://oyale.github.io/meeting-minutes/).

## Planned

### Recurring agenda points

Let a series define points that should be suggested whenever a meeting is
created. The meeting creator could include or skip each suggestion for that
meeting without changing the series.

### Add existing Odoo work to an agenda

Provide an action on project tasks, activities and native To-dos to add them as
points to an upcoming meeting. The user would choose an eligible meeting (or
create one) and the link to the source record would remain visible.

### Project context for agenda points

Allow a point to be associated with a project, so related agenda items and
follow-up tasks can stay together. Explore optional project stages that reflect
the point lifecycle without changing stages used by unrelated work.

## Under consideration

### Meeting roles and fair rotation

Allow role names such as coordinator and minutes secretary to be configured
globally or per series. Later, offer an optional rotation that suggests eligible
people fairly and still allows the organizer to make changes.

### Estimated and actual time reports

Use the meeting and agenda-point time records to show where actual durations
differ from estimates and help organizers plan future meetings.

### Domain-specific addons

Explore optional addons for specialized meeting contexts, starting with a
possible legal-meetings addon. Its scope could cover needs such as formal
notices, quorum, voting and a stronger audit trail, while keeping those rules
out of the general meeting workflow. The actual requirements and applicable
jurisdictions must be defined before committing to implementation.

# Hoja de ruta de Community Meetings

Esta hoja recoge ideas para próximas versiones. No fija fechas de entrega y las
prioridades pueden cambiar. Las funciones actuales están descritas en la
[guía de usuario](https://oyale.github.io/meeting-minutes/html-es/index.html).

## Previsto

### Puntos recurrentes del orden del día

Permitir que una serie defina puntos que se sugieran al crear cada reunión. La
persona que prepara la reunión podría incluir u omitir cada sugerencia sin
modificar la configuración de la serie.

### Añadir trabajo existente de Odoo a la agenda

Ofrecer en las tareas de proyecto, actividades y TODO nativos una acción para
añadirlos como puntos a una próxima reunión. Se podría elegir una reunión
disponible o crearla, conservando el vínculo con el registro original.

### Contexto de proyecto para los puntos

Permitir asociar un punto a un proyecto para agrupar los asuntos y sus tareas de
seguimiento. Explorar etapas opcionales de proyecto que reflejen el ciclo de
vida del punto sin modificar las etapas de otros trabajos.

## En evaluación

### Roles de reunión y rotación equilibrada

Permitir configurar globalmente o por serie los nombres de roles como
coordinación y secretaría de actas. Más adelante, ofrecer una rotación opcional
que sugiera personas elegibles de forma equilibrada y permita cambios manuales.

### Informes de duración estimada y real

Usar los tiempos registrados de reuniones y puntos para mostrar las diferencias
entre estimaciones y duración real, y ayudar a planificar futuras reuniones.

### Módulos para ámbitos específicos

Explorar módulos opcionales para contextos de reunión especializados, empezando
por un posible módulo de reuniones legales. Podría cubrir necesidades como
convocatorias formales, quórum, votaciones y una trazabilidad reforzada, dejando
esas reglas fuera del flujo general. Antes de implementarlo habría que definir
los requisitos y las jurisdicciones aplicables.
