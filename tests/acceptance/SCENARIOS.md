# Acceptance scenario matrix

This matrix records the scope, actor, preconditions, user action, expected
result, and cleanup requirements for the 25 acceptance scenarios. Stable IDs
(`cm_<area>_<number>`) link each row to its Behave feature.

Scenarios use an explicitly configured Odoo test database. The suite does not
create or drop databases or services. Fixtures use unique names and scenario-
owned records; cleanup runs even after a failed step. The caller is responsible
for database lifecycle and for records Odoo does not allow tests to delete
individually, such as generated mail or attachments.

| ID | Scope / actor | Preconditions | User action (When) | Required proof (Then) | Cleanup |
| --- | --- | --- | --- | --- | --- |
| `cm_ser_001` | Core / meeting editor | No matching series exists; editor may create one. | Enter series details and create it in the UI. | The new series is listed and reopening it shows the saved name and selected defaults. | Delete the created series and its templates. |
| `cm_ser_002` | Core / meeting editor | Series form is open; name is blank. | Submit Create Series. | Required-name validation remains active and no series is persisted. | Close the form; no series was persisted. |
| `cm_ser_003` | Core / meeting editor | A new or existing series is editable. | Add a recurring agenda template. | The saved template appears in the series and is offered when preparing a meeting in that series. | Delete the template and prepared meeting. |
| `cm_ser_004` | Core / meeting editor | An active template exists on a series. | Include it in an earlier meeting, omit it from one meeting, then include it later. | The omitted meeting has no occurrence; the template remains active; the later occurrence links to the earlier included occurrence. | Drop the disposable database; generated meeting lineage is retained. |
| `cm_lifecycle_001` | Core / editor, then distinct approver | Editor and approver accounts exist with distinct logins; no meeting is pre-created for the scenario. | Create, schedule, start, finish, prepare minutes; switch actor and approve. | The same meeting follows each state transition; approval is visible and its PDF can be downloaded. | Drop the disposable database; the held meeting, revision, and attachment are not individually deletable. |
| `cm_lifecycle_002` | Core / meeting editor | Draft meeting has no date/time. | Choose Schedule in the UI. | The date/time error appears and the meeting remains draft with no scheduled timestamp. | Delete meeting. |
| `cm_lifecycle_003` | Core / approver | A minutes draft exists with no agenda items. | Choose Approve Minutes. | The missing-agenda error or disabled-action explanation is visible; the meeting is not approved and no approved revision is written. | Drop the disposable database; the retained draft workflow cannot be deleted individually. |
| `cm_project_001` | Project / editor with required Project role | Editable meeting has an unlinked follow-up; eligible project is available. | Use Create Task, select the project, then Create and Link. | The created task persists with the selected project and meeting link; the wizard closes. | Drop the disposable database because linked tasks and meeting records persist. |
| `cm_project_002` | Project / meeting editor | Alternate-project option is selected; no project or existing task is selected. | Submit Create and Link. | The project-required error is visible; no task or follow-up link is created. | Drop the disposable database; source topics remain linked to the test series. |
| `cm_agenda_001` | Core / meeting editor | Running meeting accepts additions. | Open Add Point, enter details, and save. | The new point appears in the live agenda and its saved fields persist after reload. | Drop the disposable database after the run; the running meeting cannot be deleted individually. |
| `cm_agenda_002` | Core / meeting editor plus second session | Open Add Point while additions are allowed. | A second session closes additions; the original editor then saves the open form. | The stale save is rejected with the specified message and no new point exists. | Delete the meeting fixture. |
| `cm_calendar_001` | Calendar / attendee with meeting and Calendar read access | Scheduled meeting has an eligible linked event. | Navigate meeting → Calendar event → Open Meeting. | Both UI routes resolve to the same meeting/event identity. | Delete meeting and linked event. |
| `cm_calendar_002` | Calendar / attendee with event read access | A Calendar event exists without a meeting link. | Inspect the event actions. | Open Meeting is unavailable and no meeting link is created. | Delete event. |
| `cm_calendar_003` | Calendar / meeting editor | Scheduled meeting has a linked event and editable attendees. | Change meeting time, location, and attendees in the meeting UI. | The linked event shows the same persisted time, location, and attendee set after reload. | Drop the disposable database. |
| `cm_calendar_004` | Calendar / meeting editor | Scheduled meeting has a linked event. | Cancel the meeting in the UI. | The meeting is cancelled and its linked Calendar event is removed. | Delete remaining meeting/event records. |
| `cm_preview_001` | Core / editor or approver | Actor can read a Held meeting or a meeting with draft minutes. | Choose Preview Minutes and return to editing. | Preview shows saved content read-only; meeting state and saved draft are unchanged before and after return. | Delete meeting and draft. |
| `cm_preview_002` | Core / meeting editor | Meeting is scheduled/not held. | Attempt Preview Minutes. | The form does not offer the action; the server explains the lifecycle requirement and rejects it; no state or content changes. | Delete meeting. |
| `cm_preview_003` | Core / internal reader without editor or approver role | Actor can read the meeting but cannot edit/approve; preview is not permitted. | Attempt to open preview through the UI; verify the server endpoint under the same actor. | No preview content is exposed; UI and server both enforce the permission boundary. | Delete meeting; remove temporary reader if scenario-created. |
| `cm_proposal_001` | Core / proposer, then distinct editor | Proposal policy allows this internal user; target meeting is editable. | Submit a titled, typed proposal; editor chooses Accept. | Proposal appears for review, then an agenda point is persisted with the proposed title/type. | Drop the disposable database; accepted topics persist on the series. |
| `cm_proposal_002` | Core / proposer | Proposal form is open with title missing. | Submit the incomplete proposal. | Required-fields error appears and no proposal is persisted. | Remove the temporary series fixture. |
| `cm_carryover_001` | Core / meeting editor | Unfinished point and eligible destination meeting exist. | Request the move in the source meeting, then accept it from the destination meeting. | Request status changes and the point appears in the destination with its source relationship persisted. | Drop the disposable database; the transfer preserves cross-meeting lineage. |
| `cm_carryover_002` | Core / meeting editor | Unfinished point exists; destination selector is left empty. | Submit the carryover request. | Destination-required error appears and no valid transfer is created. | Cancel and delete the meeting fixture. |
| `cm_carryover_003` | Core / meeting editor | Accepted point has earlier debate notes and a destination meeting. | Read the context; hide it; accept the point into another meeting; restore context. | Earlier notes are separate/read-only; hiding leaves source notes unchanged and hides context in current and later continuations; restoring makes context visible again. | Cross-meeting lineage is retained; drop the disposable test database after the scenario. |
| `cm_next_review_001` | Core / meeting editor | Running meeting contains a discussion point that can be postponed. | Postpone with a reason and mark it for review next time. | Postponed state, reason, and next-meeting review choice are visible and persisted. | Cancel and delete the scheduled meeting fixture. |
| `cm_next_review_002` | Core / meeting editor | Point has next-meeting review enabled. | Reopen the meeting, clear the choice, and reopen again. | Choice is checked before clearing and remains unchecked after persistence/reload. | Cancel and delete the scheduled meeting fixture. |
